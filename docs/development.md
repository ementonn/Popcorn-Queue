# Development

Popcorn Queue is a TypeScript npm workspace.

## Packages

- `apps/api`: Fastify API, Prisma persistence, settings, diagnostics, job
  repository, and upload endpoints.
- `apps/web`: Vite/React operator UI and Playwright e2e tests.
- `apps/worker`: restartable upload preparation phases and external tool
  orchestration.
- `apps/userscript`: Tampermonkey bridge script and tests.
- `packages/core`: shared contracts, parsing, upload plans, PTP options,
  readiness, cache keys, and release description generation.
- `packages/integrations`: PTP, qBittorrent, browser check, and image-host
  clients.
- `scripts`: local setup, release asset generation, scene-group cache refresh,
  PTP login, and public release audit scripts.

## Common Commands

```bash
npm install
npm run configure
npm run dev:api
npm run dev:web
```

Run API and Web in separate shells. The Web dev server reads
`POPCORN_QUEUE_PORT` to infer the API target.

## Checks

```bash
npm test
npm run typecheck
npm run test:e2e -- --project=chromium-desktop
npm run audit:public
```

Do not run `npm test` and `npm run typecheck` at the same time in the same
workspace. `typecheck` builds package outputs that other workspaces resolve, so
parallel commands can race on generated `dist` files.

## Generated Files

- `apps/userscript/popcorn-queue-bridge.local.user.js` is generated by
  `npm run userscript:local` and ignored by Git because it can contain local
  hosts or IP addresses.
- `docs/assets/*` screenshots are generated by `npm run screenshots` from mock
  data and are safe to commit.
- `packages/core/src/generated/known-scene-groups.ts` is generated by
  `npm run scene-groups:update` and is intentionally committed.
- `dist/`, `data/`, `logs/`, `.env`, cookies, databases, torrents, and media
  files must stay out of Git.

## Test Policy

Automated tests use mocks and local fixtures. They must not call real PTP,
qBittorrent, image hosts, trackers, or external media services.

Use manual testing for real credentials and real media files. Keep manual test
notes in [manual-testing.md](manual-testing.md) when workflows change.

## Change Checklist

Before committing behavior changes:

1. Run the smallest focused test that covers the change.
2. Run `npm test`.
3. Run `npm run typecheck`.
4. Run `npm run audit:public` when documentation, generated userscripts, or
   release assets changed.
5. Check `git status --short` for accidental runtime files.
